# Деплой проекта на Firebase (пошагово)

Этот проект — Next.js с API и базой данных (Prisma + SQLite). Ниже шаги, чтобы выложить его на Firebase.

---

## Важно про базу данных

Сейчас у тебя **SQLite** (файл на диске). На Firebase App Hosting приложение крутится в **Cloud Run** — диск там временный, после перезапуска данные теряются.

**Для продакшена нужно будет перейти на облачную БД**, например:
- **Supabase** (PostgreSQL) — бесплатный тариф, легко подключить к Prisma
- **Cloud SQL** (PostgreSQL) в Google Cloud
- Или **Firestore** (тогда придётся переписать логику с Prisma на Firestore)

Первый шаг можно сделать с текущим SQLite (чтобы просто задеплоить и проверить), но для реального использования нужна облачная БД. Ниже — шаги до первого деплоя.

---

## Шаг 1. Создать проект в Firebase

1. Открой **[Firebase Console](https://console.firebase.google.com/)**.
2. Нажми **«Создать проект»** (или «Add project»).
3. Введи название, например: `fitnes-diary`.
4. При желании отключи Google Analytics (для начала можно).
5. Дождись создания проекта.

**Результат:** у тебя есть проект Firebase с уникальным ID (например `fitnes-diary-xxxxx`).

---

## Шаг 2. Тариф Blaze (обязательно для App Hosting)

Firebase App Hosting (для Next.js) работает только на **плане Blaze** (оплата по факту использования).

1. В Firebase Console открой **«Настройки проекта»** (шестерёнка) → **«Использование и выставление счетов»**.
2. Нажми **«Перейти на план Blaze»**.
3. Привяжи банковскую карту. Бесплатные лимиты большие, для учебного/малого проекта обычно укладываешься в бесплатный порог.

---

## Шаг 3. Выложить код на GitHub (если ещё не выложен)

Firebase App Hosting деплоит из репозитория GitHub.

1. Создай репозиторий на **[github.com](https://github.com)** (например `fitnes-diary`).
2. В папке проекта выполни (подставь свой URL репо):

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/fitnes-diary.git
git push -u origin main
```

**Результат:** код лежит в `main` на GitHub.

---

## Шаг 4. Подключить Firebase App Hosting к репозиторию

1. В **[Firebase Console](https://console.firebase.google.com/)** выбери свой проект.
2. В меню слева открой **«Build»** → **«App Hosting»** (или «Сборка» → «App Hosting»).
3. Нажми **«Get started»** / **«Начать»**.
4. Выбери **«Connect to GitHub»** и разреши доступ Firebase к твоим репозиториям.
5. Выбери репозиторий `fitnes-diary` (или как назвал).
6. Укажи:
   - **Root directory:** оставь пустым, если проект в корне репо; если в подпапке — укажи её (например `app`).
   - **Branch:** `main`.
   - **Region:** например `us-central1` или ближайший к тебе.
7. Нажми **«Save»** / **«Сохранить»**. Firebase создаст backend и начнёт первый сборку.

**Результат:** после успешной сборки приложение будет доступно по ссылке вида:  
`https://backend-id--project-id.us-central1.hosted.app`

---

## Шаг 5. Переменные окружения (секреты)

Локально у тебя есть `.env` (DATABASE_URL, AUTH_SECRET и т.д.). На Firebase их нужно задать в консоли.

1. В **App Hosting** открой свой backend.
2. Перейди в **«Environment»** / **«Среда»** или **«Secrets»**.
3. Добавь переменные, например:
   - `DATABASE_URL` — для продакшена лучше URL облачной БД (Supabase/Cloud SQL), а не SQLite.
   - `AUTH_SECRET` — случайная строка 32+ символов (как в `.env.example`).

После сохранения App Hosting пересоберёт и перезапустит приложение.

---

## Шаг 6. Проверить деплой

1. Открой ссылку приложения из шага 4.
2. Проверь: открывается ли главная, логин, календарь.
3. Если есть ошибки — смотри логи: в App Hosting есть вкладка **«Logs»** / **«Логи»** (или в Google Cloud Console → Cloud Run → логи сервиса).

---

## Если хочешь деплоить через Firebase CLI (без GitHub)

Тогда используется **Firebase Hosting + Cloud Run**: собираешь Next.js в Docker-образ и выкладываешь в Cloud Run, а Hosting проксирует запросы на него. Это сложнее, чем App Hosting + GitHub. Обычно проще один раз подключить GitHub и дальше деплоить через App Hosting по пушам в `main`.
